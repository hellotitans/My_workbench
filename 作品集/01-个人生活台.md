# 个人生活台 · 决策记录

> 单文件 HTML 个人工作台｜8 个板块 + AI 对话（工具调用 / 记忆 / 声场球 / 画布）｜零外部依赖｜localStorage 持久化
> 源码：https://github.com/hellotitans/My_workbench

---

## 一句话定位

一个**不需要装、不需要登录、不需要联网**的个人生活操作系统。打开就能用，关掉数据还在。
V0.1 起它还能**听你说话、替你改数据、记住你是谁、把复杂的东西画给你看**——但所有数据仍然只在这台机器的浏览器里。

---

## 关键决策

### 决策 1 · 单文件 HTML，零外部依赖

- **选项**：(A) 单文件 HTML，CSS/JS/图标全内联 ｜ (B) Vite + React 工程 ｜ (C) 引入 CDN 图表库
- **选择**：A
- **理由**：用户的核心场景是"每天打开就能用"。B 需要构建和部署，改一行要重新打包；C 的风险更硬——**用户保存的是 HTML 文件，CDN 那天 404，整个页面功能全废**。零依赖换来的最大资产是"这个文件放哪都能跑，十年后还能跑"。
- **代价**：图表和图标全部手写 SVG；没有组件复用，代码量涨到 4300 行；改样式靠全局 CSS 变量而非组件隔离。

### 决策 2 · 渲染函数之间严禁互调（单向调用 DAG）

- **背景**：曾出现日历渲染和当天列表渲染互相调用，直接栈溢出。这类 bug 语法完全正确，静态检查拦不住。
- **选择**：分层 + 统一刷新入口。数据层 `store` → 计算层 `xxxCheckin()` → 渲染层 `renderXxx()` → 调度层 `go(key)`，**渲染函数之间禁止任何互调**；多模块联动一律走顶层统一入口按固定顺序调用。
- **理由**：从架构层面杜绝循环，而不是靠人工小心。
- **代价**：任何"我改了 A 要顺带刷 B"的需求都必须回到调度层写，不能图省事在渲染函数里直接调。

### 决策 3 · 日切规则不是一刀切：全局自然日 + 建设打卡 04:00 分界

- **选择**：全局按自然日切；"习惯 Build"板块按 04:00 分界，并给 7 天补卡窗口。
- **理由**：熬夜到凌晨 1 点打卡，如果按自然日算就变成"昨天没打卡"，不符合体感，会误伤用户的连续记录。04:00 分界承认"晚睡仍是今天"。
- **代价**：两套日期函数并存（`todayStr()` / `bdToday()`），所有涉及日期的渲染必须选对，是本文件最容易出错的地方。

### 决策 4 · 没做完的事顺延，而不是清零

- **选择**：未完成项自动滚到今天，保留 `originalDate`，标红显示来源日期。
- **理由**：打卡类产品的失败模式是"断一天就弃用"。顺延把"没做完"变成可见的压力而不是消失的证据——**让用户看见自己欠了什么，比让他看不见更容易续上**。
- **代价**：今天的列表会变长，需要处理"越积越多"的观感问题（靠标红和来源日期区分新老）。

### 决策 5 · 打卡判定收敛到单一函数

- **选择**：每个模块一个 `xxxCheckin()`，统一返回 `{state: done|undone|none}`，首页打卡墙、本周概览、侧边栏三处共享同一判定。
- **理由**：同一件事如果三处各写一套判断，迟早出现"首页显示已打卡、概览显示没打卡"。单一事实源。
- **代价**：新增模块必须实现这个函数并注册进 `MODULES` 注册表，有强制约束。

### 决策 6 · 图标全部手写 SVG，禁用 emoji

- **理由**：emoji 在不同系统渲染不一致（同一个 😊 在 Windows 和 macOS 是两个表情），气质也压不住；SVG 可控、可换色、体积几乎为零。
- **代价**：每个图标要手画 path，工作量实打实。

### 决策 7 · AI 接的是协议，不是某一家（V0.1）

- **选项**：(A) 接 OpenAI 兼容协议，Base URL + 模型名 + Key 三件套 ｜ (B) 每家各写一套 SDK 适配
- **选择**：A
- **理由**：国内主流厂商（DeepSeek / 百炼 / 火山 / 智谱 / Moonshot / 硅基流动）都提供 OpenAI 兼容端点，实测**全部允许浏览器直连**（CORS 通过），所以纯前端直连即可，**不需要后端代理**。B 会让每接一家都要改代码，而用户换模型的成本应该只是改三个输入框。
- **代价**：只能用到各家协议的最大公约数；某些厂商的私有能力用不了。
- **踩过的坑**：三件套必须来自同一家，混着填是最常见的配置错误；端到端语音模型不支持 Function Calling——这一条直接决定了工具调用只能走文本对话模型。

### 决策 8 · AI 改数据必须「先让你看见，再让你点头」（V0.1）

- **选项**：(A) AI 直接写库 ｜ (B) 写操作先出预览卡，人点确认才执行 ｜ (C) 只读，不让 AI 写
- **选择**：B，且叠三道保险
- **理由**：A 的失败模式不可逆——模型误判一次，用户的一条真实记录就没了，而且用户不知道发生了什么。C 则让"帮我加个待办"这类最高频的需求整个废掉。B 的预览卡写明**从什么改成什么**，把"AI 背着我做了什么"变成"AI 做之前会问我"。
- **三道保险**：① 预览卡暂停等人确认；② 执行前全量快照入撤销栈（最近 5 次，可一键撤销）；③ 工具名归一化 + 参数校验（宁可让用户改，也不猜错数据）。
- **代价**：多一次点击。但这是**故意保留的摩擦**——写操作的确认感本身就是产品价值。

### 决策 9 · 记忆的关键不是"让模型别瞎编"，而是"瞎编的进不了库"（V0.1）

- **选择**：三道闸门 + 冲突时**并列保存不覆盖**。
  1. 结构化 schema：字段不合法整批拒收（不是修补）
  2. 来源分级：`stated`（用户明确说过）/ `inferred`（模型推断，卡片上明确标注需确认）——**没有 evidence 原话一律拒收**
  3. 敏感黑名单：健康 / 财务 / 位置 / 密钥命中即拒，**连确认卡都不弹**
- **理由**：靠提示词让模型"别乱记"是不可靠的（模型守不住规矩），但**入口处的代码校验一定守得住**。把约束力放在代码里而不是放在请求里。
- **为什么冲突不覆盖**：两条打架的记忆都可能是真的（"喜欢早上跑步"→"最近改晚上跑了"），覆盖掉一条就等于替用户做了判断。并列保存 + 标 `conflict`，让用户自己决定。
- **代价**：记忆条数会长得快一点；需要打分（置顶 + 命中次数 + 时间衰减）取 top-12 控制注入体积。

### 决策 10 · 声场球分三层，四态必须在三个维度上同时区分（V0.1）

- **选择**：`AudioEngine`（只产数据帧）→ `Skin`（只管画）→ `OrbHost`（生命周期 + 状态机）；四态 `idle / listening / thinking / speaking`。
- **为什么加第四态**：原计划只有三态。V0.2 才有 TTS，但「AI 正在吐字」本来就是一种"说"——文字一个个流出来时球体由内向外推，比"思考"好懂得多。所以 `speaking` 由**流式首个 delta** 触发，将来接 TTS 只换驱动源，接口一行不动。
- **为什么 `speaking` 和 `listening` 要在三层上都做区分**：只差一层的话两个态看起来几乎一样，用户分不清"它在听"还是"它在说"。三个维度是：
  | 层 | listening | speaking |
  |---|---|---|
  | 点阵层 | 只有外壳吃音频（声从外面进来） | 只有内壳被驱动（能量从里面推出去） |
  | 光晕 | 半径**收缩**，往里吸 | 半径**扩张** + 辐射光线 + 冲击波，往外放 |
  | 色相 | 基准（外青蓝 / 内品红） | LUT 整体旋转 −150°（外琥珀 / 内青绿） |

  实测光晕半径 idle 69.8 / listening 55.4 / thinking 80.9 / speaking 132.4，全不重叠。
- **生命周期是硬约束**：麦克风只在用户点击时申请；**离开板块必须收摊**（停 rAF + `track.stop()` + 关 AudioContext），否则后台常驻录音、系统麦克风指示灯一直亮。实测离开后音轨 `readyState:"ended"`。
- **代价**：多约 600 行；四态的视觉差异需要逐个实测标定，不能靠"看着差不多"。

### 决策 11 · 画布不让模型算坐标（V0.1）

- **选项**：(A) 让模型输出节点坐标，前端照着画 ｜ (B) 模型只给节点和边，前端做分层布局
- **选择**：B
- **理由**：模型算坐标必歪——节点会重叠、会飘出画布、间距会不均。而**拓扑分层是确定性的算法**，Kahn 分层 + 居中排列，任何输入都能给出一个不打架的结果，还能自动处理环。
- **配套**：参数全部做归一化（中英文 / 大小写 / 错字段名通吃），悬空边（指向不存在的节点）直接丢弃，重复 id 自动改名，节点不足 2 个或类型非法就**降级成文字回答**而不是画一张半截的图。
- **为什么画布渲染不打断对话**：纯展示，不该弹确认卡。只有 `plan` 的「落到今日清单 / 存成长期目标」是真写库，这时才走决策 8 的确认 + 撤销链路。
- **代价**：布局样式固定（竖向下拉），不能表达"这两个节点要并排强调"这类精细意图。

### 决策 12 · 对话页改成双栏：左边说话，右边"看见"（V0.1）

- **选择**：左对话 / 右「声场感应 + 画布空间 + 预留位」；< 1180px 回落单栏。
- **理由**：球和画布都是"展示型"的，塞进对话流会打断阅读节奏；独立成栏后，AI 在左边说话、内容在右边累积，互不遮挡。右栏留一个**预留位**，后续模块有地方放。
- **代价**：对话区变窄（748px）；矮窗口下右栏需要滚动（整体滚动而非压缩内容，避免画布被挤成 0 高度）。

## 我明确放弃的

- **不做账号体系**：一个人用的工具，靠导出/导入 JSON 迁移数据，比做登录划算得多。
- **不做后端**：没有后端就没有服务器成本、没有数据合规问题、没有运维。
- **不做浏览器通知推送**：靠"打开就看见"的置顶区（今天要处理 + 逾期标红）等价于提醒，不做推送权限骚扰。

## 失败与修正

1. **渲染函数递归栈溢出**（决策 2 的起因）——修法见上。
2. **导出 JSON 会丢数据**：`exportJSON()` 漏了 `buildBuilds` 字段，意味着用户备份的 JSON 里"习惯 Build"记录全丢，而用户不会发现，直到某天需要恢复。归档核对时才抓出来。
   → 教训：**导出功能必须和数据结构同步维护，且要有对账意识**。
3. **"习惯 Build"板块长期显示"建设中 V2"**：模块建好了但没接入打卡判定，一直走兜底分支。首页改版时才补上 `buildCheckin()`。
   → 教训：**占位状态必须有个到期检查，否则会一直在那**。
4. **存储层隐患**：`store.set` 原本没有 try/catch，隐私模式或 iframe 环境下 localStorage 会抛 SecurityError 直接卡死。补了可写性探测 + 内存降级兜底 + 明确提示。
5. **「清空全部数据」漏清 AI 记忆**（V0.1 回归时抓出）：`clearAll()` 的删除列表里没有 `memory_items`，点了"清空全部"之后画像和记住的事实还在。这是最私密的一类数据，留着就是个说不清的口子。
   → 教训同第 2 条，**"清空"这类操作必须和数据模型同步维护，而且要当成隐私功能来对待，不是当成列表维护**。
6. **底噪标定被哨兵值短路**（V0.1）：用 `noiseFloor < 0` 兼作"是否还在采样"的状态标记，安静环境下首个采样窗口为 0，赋值后再也进不去标定分支，自适应永久失效——功能没坏（兜底门限还在），但"自适应"三个字白写了。
   → 教训：**别拿哨兵值兼作状态标记，值域一碰到哨兵值就短路**。
7. **环图布局退化**（V0.1）：流程图全是环时（无入度为 0 的节点），Kahn 分层会把 3 个节点连锁推成 5 层。改为整环铺在同一层 + 虚线回边。
   → 教训：**图算法要专门测退化输入**（空图 / 单节点 / 全环 / 自环），正常输入跑得好不代表退化输入不会出丑。

## 可量化结果

- 单文件约 5900 行（V0.1），8 个板块 + AI 对话，20+ 个存储 key，**运行时除 AI 请求外零网络请求**
- 全部图标、图表、3D 球、流程图为手写 SVG / Canvas 2D，无一处外部资源引用
- 三种交付入口：本地双击启动包、线上访问页、GitHub 公开仓库（MIT）
- V0.1 回归：9 个模块无死链；导出 → 清空 → 导入数据闭环 MATCH；主题切换、四态、写操作确认撤销、记忆闸门、画布三种类型全部通过，`jsErrors: []`
- 麦克风生命周期实测：离开板块后 `active:false / raf:0 / skin:null / audio:null`，音轨 `readyState:"ended"`

## 如果重来一次

会把"导出/导入的对账测试"和"占位状态的到期检查"写进流程里，而不是靠归档时人工核对——**这两类问题都不会报错，只会静静地错**。
