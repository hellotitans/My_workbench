## 1. 路线选择：为什么第一个成果是「视觉原型」

主文件 8300 行的结构性改造**不可逆性高**——改 MODULES 和页面容器会同时牵动导航、打卡墙、本周概览、`go()` 四条链路，一旦做完很难局部回退。

而你在反馈里反复强调的是**比例失衡、结构美感、信息密度**——这些恰恰是**不需要真实数据就能验收**的东西。

所以第一步做一个**用真实皮肤、假数据**的独立原型文件：

| | 做法 | 收益 |
|---|---|---|
| ✅ 采用 | 先出 `prototype/v13-preview.html`，CSS 从主文件提取（视觉 100% 真实），数据为假 | 结构/比例/密度可反复调，**零风险、不动主文件、不动你的数据** |
| ❌ 不采用 | 直接在主文件上改 MODULES 和容器 | 一次动上千行，返工成本极高 |

原型确认后，真实改造就变成"照着已确认的图纸施工"，不再返工。

## 4. 每步的停点规则

按你的要求：**每个里程碑产出可见成果后停下，等你验收通过再进下一步。**

- 验收不通过 → 在该里程碑内迭代，不推进下一里程碑
- 每个里程碑通过后才 commit 一次（`main` 或重构分支），保持可回退
- 遇到需要你拍板的歧义 → 立即停下问，不自行假设

## 5. 铁律（改造期间不可违反）

1. **页面 id 必须等于 `page-<key>`** —— 否则 `go()` 找不到，点了没反应
2. **单向调用 DAG**：`store → xxxCheckin() → renderXxx() → go(key)`，渲染函数之间严禁互调（历史上栈溢出过）
3. **现有 19 个 DATA_KEYS 的结构定义一个都不改** —— 只新增 2 键 + 加可选字段，存量数据零迁移
4. **老数据 `domain` 为 null 时显示「待归类」** —— 不做关键词猜测（猜错比不猜更糟）
5. **写操作走「预览卡 → 确认 → 快照入栈」**
6. **图标全手写 SVG，禁用 emoji**
7. **首页面只显示动火、卡片、图表，不出现任何输入框**
8. **清空数据必须连 AI 记忆一起清**；**密钥是配置不是数据**（`llm_configs` / `asr_cfg` 保留）
9. **导出守卫**：`/key|token|secret/i` 一律剔除
10. **present_files 会污染 HTML 源文件** —— 只在 push 之后调用；验收通过后再同步劳动者包副本
