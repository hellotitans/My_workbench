### M5 · 声场球（AudioEngine → Skin → OrbHost） ✅ 已完成 2026-09-18

- [x] 从 3D_soundfield 移植数学/投影 + `AudioEngine` + 渲染核心，删 HUD/性能面板/遮罩
- [x] 四态：`idle` / `listening` / `thinking` / `speaking`（比原计划多一态，见下）
- [x] 皮肤接口落地：`create(canvas,opts)` → `{resize, frame(af,mode,t), setTheme, setPalette, dispose}`
- [x] `speaking` 与 `listening` 三层区分：点阵层内外（mask 0/1）、光晕方向（内收/外扩）、色相（LUT 旋转）
- [x] VAD：自适应底噪 1.2s（取最安静的 100ms 窗口）+ 双门限滞回 + hangover 500ms + 300~3000Hz 加权
- [x] 配色读工作台 CSS 变量，跟随亮/暗主题（浅色主题反转亮度坡：远点淡、近点深）
- [x] 麦克风仅用户主动点击时申请
- [x] **离开板块必须收摊**：停 rAF + `track.stop()` + 关 AudioContext
- [x] `visibilitychange` 隐藏时取消 rAF，回来再续
- [x] 可收起（状态存 `wb_life_orbCollapsed`）

**为什么是四态而不是三态**：V0.2 才有 TTS，但「AI 正在吐字」本来就是一种"说"——
文字一个个流出来时球体由内向外推，比"思考"更容易看懂。所以 `speaking` 由
**流式首个 delta** 触发（新增全局 `chatStreaming`），V0.2 接 TTS 时换驱动源即可，接口不用动。

**实测**（`.workbuddy/test-m5.js`，33 项全绿，`jsErrors: []`）：
- 纯函数：`fib` 400 点模长恒 1；`orbShockTrigger` 迟滞三连正确；`bandOfY` 边界 -1/0/1/2 → 0/16/31/31
- 点阵层内外：mask=0 时内壳半径恒 0.6000（等于理论 `rIn0`，不吃音频）；mask=1 时 0.8567（等于
  `(rIn0+bass*HEART_AMP)*pulse`）——数值级证明了"内外不同"
- 四态可区分：光晕半径 idle 36.4 / listening 28.8 / thinking 42.1 / speaking 68.9 全不同，
  listening < speaking（内收 vs 外扩）；mask 0 vs 1；像素签名全不同；三套 LUT 互不相同
- 麦克风：点击后 `running`、1 条音轨、`AudioContext.state = running`；底噪标定完成
- VAD 单测（不依赖真麦）：静音 1.44s 不误判 → 来声 640ms 触发 → 刚静音时 hangover 保住 → 960ms 后关闭
- 生命周期：离开板块后 `active:false / raf:0 / skin:null / audio:null`，音轨 `readyState:"ended"`
- 主题：暗色 `rgb(9,196,255)` → 浅色 `rgb(36,113,191)`；收起/展开状态持久化

**修掉的一个真 bug**：底噪标定原本用 `noiseFloor < 0` 判断是否还在采样，
但首个 100ms 窗口若为 0（安静环境），`noiseFloor` 被赋成 0 后就再也进不去标定分支，
自适应永久失效。改为独立布尔 `_calibrated`。

## 执行原则

1. **一次只做一个里程碑**，做完实测再进下一个，中途不停
2. 每个里程碑结束给出明确结论（做了什么 / 实测结果 / 下一步）
3. 遇到与文档不符的实现现实，先更新文档再继续，不悄悄偏离
4. 所有新渲染函数保持单一职责，**不与其他渲染函数互调**
5. 测试脚本继续放 `.workbuddy/test-*.js`，不入库
