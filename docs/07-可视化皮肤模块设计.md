# 可视化皮肤模块 · 设计文档

> 版本：V0.1（设计）｜ 日期：2026-09-19 ｜ 状态：设计定稿，实现排在 M5
> 首个皮肤来源：`github.com/hellotitans/3D_soundfield`（纯 Canvas 2D，零依赖）

---

## 一、定位与核心原则

这个模块是**独立于业务的可视化外壳**：它只负责"把声音和状态画出来"，不关心对话内容、不关心工作台数据。

三条原则：

1. **形状可替换**：球体只是第一个皮肤。波纹、柱状、粒子云、环形频谱……只要实现同一套接口就能挂进来切换。
2. **它必须有信息量，不能是装饰**：每种视觉状态都对应一个真实状态（在听 / 在想 / 在说 / 空闲），用户一眼能看出"它现在在干嘛"。
3. **不反向调用**：皮肤不调用任何工作台渲染函数，也不被它们调用。状态通过一个变量传递，由调度入口统一读取。

---

## 二、架构：三层分离

```
数据源层   AudioEngine   麦克风 → AnalyserNode → 每帧产出 AudioFrame
皮肤层     Skin          实现固定接口，只消费 AudioFrame，只画 canvas
调度层     OrbHost       持有当前皮肤实例、状态机、生命周期（启动/停止/销毁）
```

### 2.1 数据源层：AudioFrame

每帧产出的统一数据结构，与皮肤无关：

```
AudioFrame = {
  level,        // 0~1 整体音量（RMS 归一化）
  bands,        // 分频带能量数组（默认 12 段，低频→高频）
  voice,        // 0~1 语音活跃度（过了阈值的程度，见第四节）
  speaking      // bool 当前是否判定为"有人在说话"
}
```

**这一层是关键解耦点**：将来 V0.2 接入 TTS 播报时，AI 的声音也会走同一个 `AudioFrame` 结构喂给皮肤——皮肤不需要知道声音来自麦克风还是扬声器，只按 `OrbMode` 决定怎么画。

### 2.2 皮肤层：接口契约（新增皮肤只需实现这 6 个方法）

```
Skin = {
  id,            // 唯一标识，如 "sphere" / "ripple"
  name,          // 显示名，如 "粒子球" / "声波涟漪"
  create(canvas, opts) -> instance
}

instance = {
  resize()                       // 画布尺寸变化
  frame(audioFrame, mode, t)     // 每帧绘制，t 为时间戳（用于自转/呼吸相位）
  setTheme(theme)                // 亮/暗主题切换
  setPalette(palette)            // 配色切换
  dispose()                      // 释放资源（清 rAF、解监听）
}
```

**约束**：`frame()` 内不允许读写任何工作台状态，不允许调用其他渲染函数。它拿到的只有 `AudioFrame` 和 `mode`。

### 2.3 调度层：OrbHost

- 持有 `mode`、`当前皮肤实例`、`AudioEngine`
- 负责生命周期：**进入对话板块才创建，离开必须 `dispose()`**
- 皮肤注册表：`SKINS = [sphere, ...]`，下拉切换时 `dispose()` 旧的 → `create()` 新的

## 三、反馈模式（OrbMode）

| mode | 触发时机 | 视觉表现 | 配色倾向 |
|---|---|---|---|
| `idle` | 无交互 | 缓慢自转 + 低幅呼吸 | 低饱和冷色，安静 |
| `listening` | 麦克风开启且检测到人声 | 随声波震动，点阵被"推"出去 | 青蓝 → 紫，向内收拢的动态 |
| `thinking` | 等待首字 / 流式生成中 | 脉冲起伏，从中心向外扩散 | 琥珀/金，缓慢脉动 |
| `speaking` | **V0.2**：AI 语音播报 | 与 listening **视觉可区分** | 品红/青，向外辐射 |

**关于 `speaking` 与 `listening` 的区分**（这是原始设计的意图，先记下来）：

两者不能只是"同一个动画换个颜色"。要做三层区分：

1. **点阵层不同**：listening 用外层点阵响应（声音"进来"）；speaking 用内层点阵响应（声音"出去"）
2. **光晕方向不同**：listening 光晕向内收，speaking 向外扩
3. **色相不同**：两套不同的渐变色板，不共用

这样即便余光扫过也能分辨是"它在听"还是"它在说"。

## 四、语音活动检测：环境噪声阈值（重点）

你对"日常环境噪声非常敏感"的判断是对的。不加阈值的话，空调声、键盘声都会让球一直抖，反而失去信息量。

### 方案：自适应底噪 + 双门限滞回 + 保持时间

**1) 自适应底噪采样**
麦克风开启后前 1.2 秒作为"静音采样期"（此时提示用户"正在校准环境音"），统计这段时间的 RMS：

```
noiseFloor = 采样期的 RMS 平均值
```

**2) 双门限滞回（避免抖动）**

```
开启阈值 openThreshold  = noiseFloor * 2.5 + 0.02
关闭阈值 closeThreshold = noiseFloor * 1.5 + 0.012
```

只有超过 `openThreshold` 才判定为"开始说话"，只有低于 `closeThreshold` 才判定为"说完了"。
**两个阈值不相等**——否则在临界点会疯狂横跳。

**3) 保持时间（hangover）**
判定为"说完"后，继续保持 `listening` 状态 500ms 再回落 `idle`。人说话词之间有停顿，立刻回落会一顿一顿的。

**4) 频段加权（可选增强）**
人声能量集中在 300~3000Hz。可以只对这段频带计算活跃度，进一步压掉空调低频和键盘高频：
`voice = weighted_rms(bands[3..9])`

**5) 参数可调**
`noiseFloor` 上限、`openThreshold` 倍率、hangover 时长放进设置，默认值取上面这组。不同人的环境差异很大，留个口子。

### 状态机

```
idle ──(麦克风开启)──> calibrating ──(1.2s)──> idle(armed)
                                                  │
                          level > openThreshold   ▼
                                              listening
                                                  │
                          level < closeThreshold  │ 持续 500ms
                                                  ▼
                                                idle(armed)
```

校准期内强制 `idle`，避免开机噪声误触发。

## 五、配色：绚丽但不油腻

方向是**高饱和渐变 + 深色底**，赛博质感靠"光"而不是靠"花"：

- 每个 mode 一套 3~4 停靠点的渐变色板（LUT），运行时按能量在这条色带上取色
- 底色保持深（工作台暗色主题下尤其出效果），亮的只有粒子本身
- 亮色主题下降低饱和、提高亮度，避免糊成一片
- **禁用**：彩虹全色相随机、闪烁、屏幕抖动（会很廉价，也容易让人不适）

后续工作台整体视觉升级时，配色从 CSS 变量读取，皮肤不用改代码。

## 六、生命周期硬约束

1. **麦克风只在用户主动点击时申请**，页面加载绝不申请
2. **离开对话板块必须 `dispose()`**：停 `requestAnimationFrame` + `stream.getTracks().forEach(t => t.stop())` + 关 `AudioContext`
   —— 否则后台常驻录音，系统麦克风指示灯会一直亮，这是隐私红线
3. 页面 `visibilitychange` 隐藏时也暂停

---

## 七、新增一个皮肤的 checklist

日后你想加"波纹""环形频谱"之类，按这个走：

1. 新建对象，实现 `create(canvas, opts)`，返回含 `resize / frame / setTheme / setPalette / dispose` 的实例
2. `frame(audioFrame, mode, t)` 里**只**用传入的数据画，不碰外部状态
3. 四个 mode 都要有可区分的表现（至少 `listening` 和 `speaking` 要一眼分得清）
4. 配色统一走 `setPalette`，不写死颜色
5. 注册进 `SKINS` 数组，起一个唯一 `id`
6. 验证：切换皮肤不报错、连续切 5 次无内存泄漏、离开板块后 rAF 停止
