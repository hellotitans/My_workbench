## 一、总体架构

延续 V0.0 的**单向调用（DAG）**铁律，新增四层，每层只调下一层：

```
配置层   llmConfig      →  读/写连接配置（Key 隔离存储，不进导出）
适配层   llmChat()      →  统一 OpenAI 兼容协议：chat / stream / tools
工具层   TOOLS          →  工作台读写能力，写操作带预览与撤销
记忆层   memory         →  画像注入 + 写入闸门 + 遗忘衰减
渲染层   renderChat()   →  对话界面；renderOrb() 声场球
调度层   go('chat')     →  统一入口，按固定顺序调用各渲染函数
```

**渲染函数之间严禁互调**（V0.0 铁律 9，曾导致递归栈溢出）。对话与声场球之间没有直接调用，状态通过 `orbState`（`idle` / `listening` / `thinking`）变量传递，由事件处理函数改写、由调度入口读取。

## 二、通用接入层：为什么能用一套代码通吃

所有主流厂商都兼容 OpenAI 的 `/v1/chat/completions` 协议，因此只需三个字段即可适配：

```
Base URL  +  模型名  +  API Key
```

### 已实测的 CORS 结果（2026-09-18，本机 OPTIONS 探测）

| 厂商 | Base URL | CORS |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | 回显 Origin，允许 |
| 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `ACAO=*` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | 回显 Origin，允许 |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | 回显 Origin，允许 |
| Moonshot | `https://api.moonshot.cn/v1` | 回显 Origin，允许 |
| **硅基流动** | `https://api.siliconflow.cn/v1` | **`ACAO=*`，`ACAH=*`（最宽松）** |
| Google | — | **不通（国内网络）** |

**结论：纯前端直连完全可行，不需要后端代理。** 单文件零依赖的铁律守得住。

### 两个必须处理的差异

1. **流式**：统一用 SSE（`stream: true`），解析 `data: ` 行，遇 `[DONE]` 结束。各家一致。
2. **工具调用**：`tools` / `tool_calls` 格式基本一致，但**国产模型稳定性参差**。适配层必须做：
   - 解析失败重试一次，仍失败则降级为"纯文本回答 + 提示未生效"
   - 校验返回的 `arguments` 是合法 JSON，非法则丢弃该次调用（不让脏数据进工具层）
   - 工具名做归一化（中英文 / 大小写 / 后缀通吃）——避免模型照抄中文标签导致静默丢弃

## 三、工具层：写操作的三道保险

工作台是用户的**唯一数据源**，误写代价高，所以写操作不能交给模型直接执行。

```
模型返回 tool_call
   ↓
① 结构校验（工具名在白名单内？参数合法？）
   ↓
② 预览卡：用自然语言说明"将要做什么、改成什么"，附变更前的值
   ↓
③ 用户确认 → 执行 → 保存操作前快照到 undoStack（保留最近 5 次）
   ↓
④ 结果回灌给模型，让它用自然语言复述结果
```

- 读操作（查询类）免确认，直接执行
- 工具失败要**可见**：把错误原文返回给模型并展示给用户，不让模型自己圆过去
- `undoStack` 只存快照，不存操作日志，避免长期膨胀

### 3.1 已实现形态（M3，2026-09-18）

- 工具声明 `TOOLS`（OpenAI function calling 格式）：6 个 ——
  读：`get_today` `get_board`；写：`add_todo` `done_todo` `add_memo` `build_checkin`
- 实现 `TOOL_IMPL`：读工具 `run(args)` 直接返回文本；写工具 `plan(args)` 只产出
  `{label, rows:[{k, from, to}], apply}`，**落库动作只在用户点确认后才发生**
- 调用循环：`chatRound()` 一次模型调用为一轮，`chatRunTools()` 逐个执行 tool_call，
  读完/确认后回灌 `role: "tool"` 消息再进下一轮，`TOOL_MAX_ROUNDS = 3` 防模型陷入循环
- 流式也带 tools：SSE 分片的 `delta.tool_calls` 按 `index` 合并，
  流式失败时回退非流式（同样带 tools）重试一次
- 预览卡本身是**历史消息**（`role: "tool"` + `state`），刷新后仍在；
  撤销快照存 `wb_life_chat_undo`（最近 5 次），**不进 exportJSON**（已实测 CLEAN）
- 三处兜底：工具名归一化 `chatNormTool`、参数宽松解析 `chatParseArgs`、
  写工具参数不合法时不产卡片，直接把原因回灌给模型让它自己改

## 四、记忆层：三条策略如何真正约束住模型

### 核心原则

> **不要靠"在系统提示里写规则"来约束模型。**
> 规则只降低违规概率，闸门才决定结果。模型一定会偶尔不守规矩，所以必须假设它会违规，然后在代码层让违规行为**无法产生后果**。

三层配合：

```
提示词层（软）  →  降低违规概率
结构化层（中）  →  限制输出形态，只让模型"填空"
代码层（硬）    →  校验、分级、拦截 —— 真正的执行者
```

### 4.1 系统提示：四段式（规则要短、要具体）

```
[1] 身份与语气      —— 是谁、怎么说话（沿用工作台"积极直白催行动"的调性）
[2] 用户画像        —— L0 注入，用户可编辑的那段文本
[3] 记忆写入规则    —— 什么能写、什么不能写、输出什么格式
[4] 工具调用规则    —— 能调什么、写操作必须走预览
```

写规则的经验约束（来自本项目此前的实测教训）：

- **要求必须给出具体数字**，不要给软要求。"最多提议 2 条"有效，"不要提议太多条"无效
- **写明违规后果**。"超出会被丢弃"比"请遵守"有效
- **控制在短篇幅**。规则越长遵守度越差——宁可拆成结构化字段，也不要堆一大段散文

### 4.2 闸门一：结构化输出 + schema 校验

模型想写记忆，不允许输出自由文本，只能输出：

```json
{
  "memories": [
    {
      "type": "preference | habit | project | term",
      "content": "简短陈述",
      "evidence": "用户原话片段",
      "source": "stated | inferred",
      "confidence": 0.0
    }
  ]
}
```

代码层校验（任一项不过 → **整批丢弃**，不入库、不报错打扰用户）：

- `type` 必须在枚举白名单内
- `content` 长度 ≤ 60 字
- `evidence` 非空
- `confidence` 落在 0~1

### 4.3 闸门二：来源分级（写入权限）

| source | 含义 | 处理 |
|---|---|---|
| `stated` | 用户明说，且带证据引用 | **自动入库** |
| `inferred` | 模型推断 | **必须用户确认**，不确认不入库 |
| 缺失 / 其他 | — | 拒收 |

**防幻觉污染的关键就在这里**：不是"让模型别瞎编"，而是"**瞎编的东西进不了库**"。两道锁：

1. 没有 `evidence`（引用的用户原话）→ 一律拒收
2. 凡是"推断"类 → 必须过人

### 4.4 闸门三：敏感黑名单 + 冲突检测

- **黑名单**（写在代码里，不交给模型判断）：健康数据、财务金额、他人信息、密码/密钥、位置轨迹 → `deny`，直接拒绝并提示用户
- **冲突检测**：新记忆与已有记忆语义冲突时**不覆盖**，标为 `pending_conflict`，交给用户裁决。覆盖是危险的——一旦被错误记忆覆盖，原始信息就永久消失了

### 4.5 遗忘策略

每条记忆字段：`created_at` / `last_hit` / `hit_count` / `pin`。

注入上下文时打分排序，只取 top-N（默认 12 条）：

```
score = 时间衰减(last_hit) + log(1 + hit_count) + (pin ? 加分 : 0)
```

- 90 天未被命中 → 转**冷存**：不进上下文，但保留、可搜索、可手动恢复
- 用户始终可删除 / 置顶 / 编辑
- **不设自动删除**。记忆的删除权归用户，代码只做降权

## 五、声场球移植方案

### 来源评估

`github.com/hellotitans/3D_soundfield` 的 `index.html`（49KB）：

- **纯 Canvas 2D + 手写 3D 投影**（斐波那契球布点 + `spin`/`tilt`/`project` 变换），**无 three.js、无任何 CDN**
- 核心两个类：`AudioEngine`（`getUserMedia` + `AnalyserNode` + 分频带提取）、`SphereRenderer`（渲染循环 + 主题 LUT）
- 结论：**可直接内联移植，不需要 iframe**，不违反零外部依赖铁律

### 移植裁剪

| 原项目部件 | 处理 |
|---|---|
| 数学与投影（`fib`/`spin`/`project`/`band*`） | 保留 |
| `AudioEngine` | 保留 |
| `SphereRenderer` 渲染核心 | 保留 |
| HUD / 性能面板 / 启动遮罩 / 独立配色选择器 | **删除**（工作台已有主题系统） |
| 配色 LUT | 改为读工作台 CSS 变量，跟随亮/暗主题 |

预估增加约 500~700 行，主文件从约 4300 行增至约 4900~5000 行。（实测：M5 落地后主文件 333,277 字节 / 5903 行。）

### 状态机（M5 落地版，四态）

```
idle      待机：缓慢自转 + 低幅呼吸，无音频输入
listening 聆听：麦克风开着，外壳吃频谱（mask=0），光晕内收
thinking  思考：已发出请求、尚未吐出第一个字，合成扫描波纹 + 自转 ×1.9
speaking  说话：流式首个 delta 到达（V0.2 换 TTS 播放状态），内壳驱动（mask=1），光晕外扩 + 冲击波
```

优先级：`chatStreaming` > `chatBusy` > `mic` > `idle`。
状态由 `OrbHost.modeOf()` 每帧**读取**现有全局量得出，渲染函数不去反过来改写它们——**不做反向调用**。

**为什么 `speaking` 和 `listening` 必须三层区分**（否则两个态长得几乎一样）：

| 层 | listening | speaking |
|---|---|---|
| 点阵层 | `mask=0` 只有外壳吃音频（声从外面进来） | `mask=1` 只有内壳被驱动（能量从里面推出去） |
| 光晕 | 半径**收缩**（实测 28.8px）→ 往里吸 | 半径**扩张**（实测 68.9px）+ 辐射光线 + 冲击波 → 往外放 |
| 色相 | 基准 LUT（外青蓝 / 内品红） | LUT 整体旋转 −150° → 外琥珀 / 内青绿 |

`thinking` 用 +75°（外蓝紫 / 内橙黄），与两者都不撞。

### 语音活动检测（VAD）

`AudioEngine` 除频段外还产一个 `vf`（300~3000Hz 人声频段加权电平），判定链：

1. **自适应底噪**：开麦后 1.2s，每 100ms 一个窗口，取**最安静**的那个窗口 ×1.25，下限 0.0015
   （取 min 而不是均值——用户开麦就开始说话也不会把底噪顶高）
2. **双门限滞回**：起音 `nf*2.5+0.02`、收音 `nf*1.5+0.012`，两个阈值不相等才不会在门限上抖动
3. **hangover 500ms**：掉到收音门限以下还撑 500ms，字与字之间不断裂

### 两条硬性约束

1. **麦克风只在用户主动开启时申请**，页面加载绝不申请权限（进板块只建皮肤，不碰 `getUserMedia`）
2. **离开对话板块必须收摊**：`cancelAnimationFrame` + `skin.dispose()` + `audio.stop()`
   （`track.stop()` + `ctx.close()`）。否则后台常驻录音，系统麦克风指示灯会一直亮。

实测离开后：音轨 `readyState:"ended"`、`raf:0`、`skin:null`、`audio:null`。
`visibilitychange` 隐藏时同样取消 rAF，回来再续——不做无用功。

### 皮肤接口（后续加形态照抄这个契约）

```js
create(canvas, opts) → {
  resize(),                    // 尺寸/dpr 变化后重建几何缓存与渐变
  frame(audioFrame, mode, t),  // 每帧一次，audioFrame 可为 null（无音频时纯呼吸）
  setTheme("dark"|"light"),
  setPalette(paletteObj),
  dispose()                    // 断 ResizeObserver + 清画布
}
```

新增形态只需往 `ORB_SKINS` 注册一个同签名工厂，`OrbHost.skinKey` 指过去即可，宿主与音频层一行都不用改。

## 六、画布空间：AI 把结构化内容落到面板上

### 为什么不让 AI 输出 markdown 再解析

markdown 是给人看的排版格式，不是给程序读的数据结构。让模型吐 markdown、前端再正则提取，
中间任何一环的格式漂移（多一个空格、换个标题层级）都会静默失败。**改为工具调用**：
AI 调 `render_canvas`，参数是结构化 JSON，前端按 schema 渲染。

### 三种类型

| type | 触发场景 | 渲染 |
|---|---|---|
| `explain` | 需要展开解释的「为什么 / 是什么 / 原理」 | 一句话结论 + 2~4 个要点 + 类比 + 常见误解 |
| `plan` | 「我想达成 X，怎么拆」 | 目标 → 阶段 → 步骤阶梯，底部两个落库按钮 |
| `flow` | 流程 / 逻辑 / 因果 / A 与 B 的关系 | 手写 SVG，自动分层布局 |

### 流程图：模型只给节点和边，坐标由前端算

模型算坐标必歪（重叠、飘出画布、间距不均）。所以 **nodes / edges 里没有坐标字段**，
前端用 Kahn 拓扑排序分层：

1. 入度为 0 的节点放第 0 层，逐层推进 `layer[j] = max(layer[j], layer[cur]+1)`
2. **环的处理**：环内节点入度永远降不到 0，Kahn 结束后仍有 `layer < 0` 的，统一放最后一层
3. **全环的退化输入**：若没有任何入度为 0 的节点，不让 BFS 硬跑（否则 3 个节点会被连锁推成 5 层），
   直接把整环铺在第 0 层，连线走虚线回边样式
4. 每层节点水平居中排列；回边（`to.y <= from.y`）走侧面贝塞尔 + 虚线，和正向线区分开

### 归一化与降级（代码兜底，不靠模型守规矩）

| 风险 | 处理 |
|---|---|
| type 写成中文 / 大小写 / 前缀 | `cvNormType()` 正则 + 前缀通吃；认不出来就报错 |
| points 给成字符串数组而非对象数组 | `cvPairs()` 两种都收 |
| 字段名叫 `desc` 而不是 `d` | 多个别名依次尝试 |
| 悬空边（`from` 指向不存在的节点） | **直接丢弃**，不画 |
| 自环（`from === to`） | 丢弃 |
| 重复节点 id | 自动改名（`x` → `x_1`） |
| 节点不足 2 个 / 类型非法 / 内容为空 | 返回 `error`，**让模型改用文字回答**，不画半截图 |

最后一条是关键：降级路径必须是"改用文字回答"，不是"画一张缺东西的图"。
半张图的伤害比没有图大。

### 画布不打断对话，落库才打断

`render_canvas` 是 `show` 类工具（区别于 `read` / `write`）：直接渲染，**不弹确认卡**，
模型收到的结果是"已画到右侧画布，正文只写一两句概括"。

只有 `plan` 卡片上的「加进今日清单 / 存成长期目标」是真写库——这时复用 M3 的写操作链路
（预览卡 + 快照 + 撤销栈），点一下在对话里生成一张待确认卡。**展示归展示，写库归写库。**

## 七、语音输入（V0.2 M8）：声音 → 文字 → 等人点头

### 为什么必须自己采 PCM

直觉方案是 `MediaRecorder` + `audio/webm`，但它有个致命细节：**webm 只有第一个分片带文件头**。
按句切出来的第二、三、四段没有头，服务端解不开。要么每次 stop/start（切段有间隙、会丢字），
要么把历史 chunk 一起带上（越录越大、重复识别）。

所以改为 `ScriptProcessorNode` 直接拿 Float32 采样 → 手动封装 16bit 单声道 WAV：
每一段都是完整可解码的，采样率压到 16kHz，体积只有 48k 的三分之一。

```
麦克风流 ──▶ MediaStreamSource ──▶ AnalyserNode（给球体）
                              └──▶ ScriptProcessor ──▶ Gain(0) ──▶ destination
                                        │
                                        └─▶ 重采样 16k → 累积 → 断句 → WAV → POST
```

`Gain(0)` 是必需的：不连到 destination 音频图不运转，连了又不能出声（否则啸叫）。

### 断句参数（实测标定）

| 参数 | 值 | 为什么 |
|---|---|---|
| 底噪标定 | 开麦后 1.2s，取最安静窗口 ×1.3 | 与声场球同一套思路；标定期间不收音，避免把开麦那一下当第一句 |
| 起音门限 | `nf × 3.0 + 0.006` | |
| 收音门限 | `nf × 1.9 + 0.003` | 比起音低 → 形成滞回，避免一个字一顿 |
| 静音切句 | 700ms | 正常说话的词间停顿远小于此 |
| 最短句长 | 0.35s | 过滤咳嗽、敲桌子 |
| 最长句长 | 25s（强制切） | 防止请求过大 |
| 尾部裁剪 | 切掉尾静音，保留 120ms | 见下 |

**尾部静音必须裁**：等待静音判定那 700ms 的采样一开始也被算进了音频，导致每句话都拖着
0.7 秒空白（请求凭空大 60%），而且一声咳嗽「0.17s 声音 + 0.68s 静音」会凑够最短句长被当成一句话。
现在记录尾部静音长度、切段时裁掉，留 120ms 余量防止削掉最后一个字。

### 保序

请求可能并发、返回可能乱序。用 `seq`（发出序号）+ `expect`（期望落字的序号）：
先到的"第二句"暂存，等"第一句"回来一起按顺序落，保证语序不乱。

### 三条硬约束

1. **绝不自动发送** —— 转写结果只填进输入框，发出去永远由用户按 Enter / 点发送
2. **追加不覆盖** —— 连续说话累积，用户随时可改
3. **识别挂了不打断** —— 只是没有文字，声场球照常转，不弹错误框

### 降级链

```
配了密钥 → 云端 ASR（硅基流动 SenseVoiceSmall）
   ↓ 没配 / 请求失败
浏览器自带识别（webkitSpeechRecognition）
   ↓ 不支持 / 被拒 / 连不上
提示去配置，球体照常
```

## 八、数据模型（新增 key，前缀 `wb_life_`）

| key | 内容 |
|---|---|
| `llm_configs` | 连接配置数组（**不含于导出**） |
| `llm_active` | 当前选中的配置 id |
| `asr_cfg` | 语音识别配置（**不含于导出**） |
| `chat_sessions` | 按天分组的对话历史 |
| `user_profile` | L0 用户画像文本 |
| `memory_items` | 记忆条目（含 `source`/`hit_count`/`last_hit`/`pin`） |
| `undo_stack` | 写操作前快照（最近 5 次） |
| `canvas_docs` | 画布内容（最多 8 张） |
| `orbFolded` | 声场感应面板是否收起 |

`exportJSON()` 必须显式排除 `llm_configs` 与 `asr_cfg`——这是 V0.1 起的硬性验收点。
导出时还有一道正则兜底（`/key|token|secret/i`），即便误加也会被拦掉。

## 九、已知风险

| 风险 | 应对 |
|---|---|
| 国产模型 `tool_calls` 不稳定 | 重试 1 次 + 参数 JSON 校验 + 工具名归一化；失败降级为纯文本 |
| `file://` 下麦克风行为不确定 | 声场球以线上 https 版为主，本地做降级提示（不支持/被拒时球体保持呼吸） |
| 模型往画布塞超长文本 / 过多节点 | 所有字段在入口 `cvClip()` 截断；节点上限 10、边上限 14、画布上限 8 张 |
| 模型把不该画的东西画上去 | 参数不合法就降级，让它改用文字回答；不重试、不留半截图 |
| 流程图布局在极端输入下出丑 | 空图 / 单节点 / 全环 / 自环四种退化输入均有测试覆盖 |
| 上下文膨胀 | 历史限 N 轮 + 记忆限 12 条 + 工具定义精简 |
| 主文件膨胀至 ~7460 行 | 渲染函数保持单一职责；如需再拆，仍坚持单文件内联，不引入构建 |
| 语音识别端点不通 | 十家实测只有硅基流动满足「直连 + 通用格式」；失败自动降级到浏览器自带识别，再失败只提示不打断 |
| `ScriptProcessorNode` 已废弃 | 目前各浏览器仍可用；将来若被移除，改为 AudioWorklet（需 Blob URL 加载模块，仍是单文件） |
| 转写把环境音当话 | 底噪标定 + 双门限滞回 + 最短句长 0.35s + 尾静音裁剪，四层过滤 |
