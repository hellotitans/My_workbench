| 项 | V1.2 | **V1.3** | 原因 |

## 1. 第一性原理

### 1.1 工作台是「每日减熵装置」，不是档案柜

你的原话是"抵抗每天的熵增带来的混乱无序"。熵增的对立面不是"记录"，是**整理**——把无序状态变成可判断的状态。

推论：设计目标是**让每天的判断变容易**，不是让每天的记录变完整。任何要求你"为了填满而填"的字段都是反目标。

### 1.2 模块取舍的唯一标准：沉淀价值

你自己定的原则是"只记提炼，不记流水账"。落到取舍上就是一条：

> **这个模块记满 90 天后，回头看能得出什么结论？**
> 得不出结论的，就是流水账 —— 砍掉。
> 能得出趋势、能指出问题、能变成行动依据的 —— 才值得结构化。

| 模块 | 90 天后能得出什么 | 判定 |
|---|---|---|
| 饮食（每天 4 个输入框） | 无热量、无营养分析 → **什么都得不出** | **删除** |
| 游戏娱乐 | 无 | **删除** |
| **健身** | 训练量趋势、部位覆盖、动作瓶颈、心法库 | **升级为主模块** |
| **博主视频** | 一条持续增长的启发库 | **结构化保留** |

### 1.3 为什么删除状态档位（V1.2 核心修正，沿用）

档位（好/平/差、突破/停滞/内耗…）有三条不可修复的缺陷：

| 缺陷 | 说明 |
|---|---|
| **不指向动作** | 写下"停滞"不会让项目动起来，写下"内耗"不会解决内耗。它是形容词，不是可操作对象。 |
| **单日不可比** | 每天基线不同，周一的"平"和周五的"平"不是一个意思。 |
| **必然退化** | 任何"每天必选一次"的定性字段，第三天起就会变成随手点同一个选项。 |

**替代的第一性原理：状态的真正载体不是感觉，是事实。**

- 推进型领域（开发 / 学习）：状态 = **未闭合卡点的存在与年龄**
- 维持型领域（身体 / 心智）：状态 = **与自身基线的偏离** / **在修课题的进展**

共同点：**全部由系统算出来，不需要你填。**

### 1.4 四个类目 = 每天要整理的四个状态

| 类目 | 整理什么 | 未闭合项在此领域的形态 | 命名状态 |
|---|---|---|---|
| **开发** | 独立 AI 项目的推进状态 | **技术卡点** | 已定 |
| **学习** | 新技术与理论的**学习与应用**状态 | **概念卡点** / 学而未用的知识 | 已定 |
| **身体** | 身体状态（**健身** / 睡眠 / 体重） | **健身卡点**（瓶颈 / 伤痛 / 平台期）+ **偏离项**（系统自动检测） | 已定 |
| **心智** | 心理与**习惯**状态（习惯打卡 / 认知自塑 / 心得心法） | **在修课题**（复用神经回路自塑条目） | **已定，保留「心智」** |

> 四领域共用同一个对象 `openItem`，只是显示名与生成方式不同。这是**同构性**的来源——学会一个领域，其余三个立刻会。

### 1.5 巩固与变异（你自述的区分，最高杠杆的一条）

| 动力 | 字段 | 本质 | 设计推论 |
|---|---|---|---|
| **巩固** | 每日正反馈 | 对已完成行动的自我确认，让下次更容易启动 | **不该手写** —— 从今日完成项与已关闭卡点自动生成候选，点选即可 |
| **变异** | Make a difference | 跳出重复日常，防止认知行为僵化 | **不该是空文本框** —— 做重复度检测并主动提醒 |

### 1.6 频率分层：8 步不是一条直线

| 档位 | 内容 | 说明 |
|---|---|---|
| **每日 4 步** | ① 观察评估 → ② 定当日计划 → ③ 记录执行 → ④ 确认达成 | 每天真正要走的全部 |
| **触发（遇到才记）** | 定义新卡点 / 填方案与效果 | **卡点不是每天都有，硬找是内耗** |
| **每周 1 次** | 回看进展 → 定位显著问题 → 规划下一步方向 | 对比目标回看进展是周度动作 |

## 3. 信息架构

### 3.1 两层正交

```
   今日：观察 → 行动 →（收尾页）→ 周复盘
        ↑        ↑         ↑          ↑
   开发 ─┴────────┴─────────┴──────────┘
   学习 ─┴────────┴─────────┴──────────┘
   身体 ─┴────────┴─────────┴──────────┘
   心智 ─┴────────┴─────────┴──────────┘
（纵切面·状态类目）  ↑
              首页（横切面·只读聚合）
```

### 3.2 铁律

1. **首页只读不写** —— V1.3 起首页无任何输入框，结构上不可能违反
2. **今日待办只有一个来源** = 四领域 S2 的今日计划（含短期计划一键加入）
3. **记录不打断首页流程** —— 今日清单项可就地展开记一句，不必跳领域页
4. **不设每日必填的"问题"** —— 卡点是触发式
5. **系统只提示，不代你定义卡点** —— 判断权在人
6. **沉淀价值是模块取舍的唯一标准**（§1.2）

### 3.3 导航（V1.3：取消顶栏捕捉）

```
顶栏（全局）
  ├─ 日期 / 问候 / 陪伴天数（压缩）
  └─ 「收工」按钮 → 进入收尾页
  （无快捷捕捉、无快捷键呼出 —— 写操作全部在领域页内）

侧栏
  ├─ 今日（首页 dashboard）
  ├─ 开发
  ├─ 学习
  ├─ 身体
  ├─ 心智
  ├─ 周复盘
  └─ 数据与备份（hide）
```

## 4. 核心对象模型

### 4.1 未闭合项 Open Item

```js
openItem = {
  id,
  domain: 'dev'|'study'|'body'|'mind',
  title,                                // 一句话：到底是什么挡着
  impact,                               // 可选：它挡住了什么
  state: 'open'|'solving'|'solved'|'parked',
  createdAt, solvingDate, solvedAt,
  solution,                             // 方案（转 solved 时填）
  effect,                               // 效果（转 solved 时填）
  ref: { key, id } | null,              // 引用已有对象，避免内容分裂
  snapshotText: string|null             // 被引对象删除后的文本快照
}
```

### 4.2 四态状态机

| 状态 | 含义 | 进入条件 | 离开条件 |
|---|---|---|---|
| **open 待解** | 已定义，还没排进某天 | 手动新建（触发式） | 挂进今日 → `solving`；明确不做 → `parked` |
| **solving 今日在解** | 今天正在处理 | 定当日计划时挂进今天 | 解决 → `solved`；**隔日未解决自动回退 `open`** |
| **solved 已解** | 已解决，附方案与效果 | 填完方案 + 效果 | 终态 |
| **parked 搁置** | 主动放下 | 手动搁置 | 可重新激活为 `open` |

**关键规则**：每天开始时，昨日 `solving` 但未解决的项**自动回退为 `open`** 并累计停滞天数。
→ 保证"今日在解"永远是干净的"今天"，同时让停滞天数成为真实信号。

### 4.3 各领域的生成方式

| 领域 | 显示名 | 来源 |
|---|---|---|
| 开发 | 技术卡点 | 手动新建；系统提示"项目 X 停滞 N 天" |
| 学习 | 概念卡点 | 手动新建；系统提示"某知识点学了 N 天未应用" |
| **身体** | **健身卡点** | **手动新建**（动作瓶颈 / 伤痛 / 平台期）；**偏离项**（系统自动生成） |
| 心智 | 在修课题 | 引用 `buildNeuro`（神经回路自塑）条目 |

**身体偏离项自动检测**（实时计算，不落库）—— **V1.3 已删除饮食维度**：

| 指标 | 偏离判定 | 阈值状态 |
|---|---|---|
| 睡眠 | \|今日 − 30 日均值\| ≥ X 小时 | **待实跑标定** |
| 体重 | \|今日 − 30 日均值\| ≥ X kg | **待实跑标定** |
| 训练 | 连续 N 天无训练记录 | **待实跑标定** |

> 阈值一律**实跑标定**，不拍脑袋设。先跑两周看分布，再回填。

### 4.4 ref 级联规则（已定）

```
被引对象被删除时：
  1. 卡点本身保留，不级联删除（卡点是一条独立事实）
  2. ref 置为 null
  3. 把被引对象的标题文本写入 snapshotText
  4. 显示时标注「原引用已删除」，其余功能不变

反向：卡点被删除，不影响被引对象。
```

### 4.5 三级计划链（V1.3 新增）

```
长期计划（goals）     例：3 个月体脂降到 22%
   ↓ 拆解
短期计划（shorts）    例：本月完成 12 次力量训练     ← 可一键「加入今日」
   ↓ 拆解
今日计划（todays）    例：今天练背                   ← 可挂短期计划，也可空挂
   ↓ 汇入
首页 · 今日待办       打勾 / 就地记录
```

**数据层处理（关键：不新建键）**

| 现有键 | 改动 |
|---|---|
| `goals` | 新增可选 `domain` 字段 |
| `shorts` | 新增可选 `domain` 字段 |
| `todays` | 新增可选 `domain` 字段 + 可选 `shortId`（关联的短期计划，可空） |

- **向后兼容**：老数据 `domain` 为 `null`，在领域页显示为「待归类」分组，可一键归类。**不做关键词猜测**——猜错比不猜更糟。
- 现有 19 键的**结构定义与既有字段语义一律不改**。

## 5. 领域页骨架：四段对应每日四步

| 段位 | 对应每日哪一步 | 内容 |
|---|---|---|
| **S1 观察 · 未闭合项** | ① 观察评估 | 未闭合项列表（含停滞天数）+ 系统自动数字 + 今日焦点。**无待填的定性字段** |
| **S2 计划链** | ② 定当日计划 | **长期 → 短期 → 今日**三级；短期计划可一键加入今日；今日计划可挂短期也可空挂 |
| **S3 执行记录** | ③ 记录执行 | 各领域不同（见下表）；默认一句话，遇到问题时展开「问题/解法/结果」 |
| **S4 沉淀与回看** | ④ 确认达成 + 复盘 | 已关闭卡点的方案与效果 + 本领域积累 + 趋势图 |

| | S1 未闭合项 | S2 计划链 | S3 执行记录 | S4 沉淀与回看 |
|---|---|---|---|---|
| **开发** | 技术卡点 | 长期目标 → 里程碑 → 今日任务 | 推进了什么、卡在哪 | **已解卡点（方案+效果）** · 灵感 · 心得 |
| **学习** | 概念卡点 | 学习目标 → 阶段 → 今日学习 | 学了什么、用在哪 | **已解卡点** · 知识树（五关系）· 应用记录 |
| **身体** | 健身卡点 + 偏离项 | 身体目标 → 月计划 → 今日训练 | **健身五件套**（§6） | **健身心法库** · 体重趋势 · 训练量趋势 |
| **心智** | 在修课题 | 心智课题 → 主题 → 今日习惯/自塑 | 习惯打卡 / Build | **已解课题** · 心得 · 心法库 |

### S1 的展示形态

```
开发 · 观察                                    [+ 记一个卡点]
  未闭合 3 项   最老卡了 6 天   今日在解 1 项
  ├ ● RAG 检索召回率上不去            卡了 6 天   [今天解决] [搁置]
  ├ ● 多轮对话上下文膨胀              卡了 3 天
  └ ○ 推理延迟超标（系统检测·项目停滞） 卡了 1 天
```

- **没有状态档位、没有每日必填的形容词、没有随手记输入框。**
- 卡点触发式新建，没有就不建。
- 你每天在这里只做一件事：**决定今天碰哪个卡点**。

## 6. 身体领域 · 健身模块详细设计

> 这是身体领域的主体。饮食与娱乐已删除，身体领域不再有流水账。

### 6.1 五件套（对应你的原话）

| # | 你的原话 | 模块 | 位置 | 粒度 |
|---|---|---|---|---|
| 1 | 对身体状态的观察评估 | **状态观察** | S1 | 系统自动（偏离项检测）+ 一句话体感（可选） |
| 2 | 每天进行了什么内容的健身 | **训练记录** | S3 | 部位标签 + 内容 + 时长/量 |
| 3 | 健身动作的感受体会和心得 | **动作感受** | S3 | 一句话（挂在训练记录上） |
| 4 | 每天看一个健身博主视频的结论和启发 | **博主启发** | S3 | 博主 + 主题 + 结论 + 启发 |
| 5 | 沉淀出的健身习惯 | **健身心法** | S4 | 一条原则（可溯源到哪条启发） |

### 6.2 训练记录（中等粒度：可回看对比即可）

```js
fitnessLog = {
  id, date,
  parts: ['背','腿','胸','肩','核心','有氧'],  // 多选标签
  content,                                     // 训练内容（一句话）
  volume,                                      // 时长 / 量的自由数值（如 "45min" "12 组"）
  feel                                         // 动作感受与体会（一句话）
}
```

**不采集**组数 / 重量 / 组间休息 —— 那是训练日志 App 的事，会让录入成本压过沉淀价值。

### 6.3 博主启发

```js
fitnessVideo = {
  id, date,
  author,        // 博主
  topic,         // 主题
  conclusion,    // 得到的结论
  insight        // 对我的启发
}
```

- 有则记，无则不记（**不是每日必填**）
- 连续记录天数自动计算并显示（不与缺失日断链）
- 列表按时间倒序，可按博主筛选

### 6.4 健身心法（沉淀层）

```js
fitnessPrinciple = {
  id, text,          // 一条原则，如「深蹲前先激活髋」
  from,              // 溯源：来自哪条启发 / 哪次训练
  createdAt
}
```

**归属判定（已定）**：健身心法**留在身体领域 S4**，不进心智的习惯打卡。

- 边界：**身体领域存知识，心智领域管执行。**
- 若某条心法你想变成每日执行的习惯 → 手动加进心智领域的习惯打卡（一次主动操作，不是自动同步）。
- 理由：自动同步会让两个领域出现同名条目，边界糊掉；手动一次反而让你确认"这条我真的要每天做"。

### 6.5 身体领域的图表

| **训练量趋势** | 按周的时长/组数累计 | 看训练节奏是否稳定 |

## 7. 首页（今日横切面）

三层，从上到下是「观察 → 趋势 → 行动」：

| 层 | 内容 |
|---|---|
| **L1 观察** | 四个领域卡（等宽）：未闭合项数 + 最老停滞天数 + 今日在解数 + 今日焦点。全为系统算出的数字 |
| **L2 焦点图表** | 四领域推进曲线（默认）/ 卡点累积与解决曲线 / 学习项目产出量。内联 SVG，零图表库 |
| **L3 今日行动** | **只显示四领域 S2 汇入的今日计划**；打勾 + 就地展开记一句（进展 / 解法 / 结果） |

**首页没有任何输入框** —— 快速备忘已删，全局捕捉与快捷键已取消。
今日待办唯一来源 = 领域页计划链。写操作全部发生在领域页。

**删除**：快速备忘、顶栏捕捉、快捷键、本周打卡 7×7（升级为 L2）、日期大卡（压进顶栏）、状态档位。
**不含收尾** —— 收尾走独立页。

## 8. 完成反馈

> 原则：**反馈的份量要与事情的份量匹配。**

| 层级 | 触发 | 反馈 |
|---|---|---|
| **① 微反馈** | 待办打勾 | 对勾描边动画 + 条目下沉 + 顶部计数 +1。**约 200ms，不弹窗** |
| **② 强反馈** | **关闭一个卡点**（填完方案+效果） | 卡点收束为已解态 + 浮出战报小卡（卡了 N 天 / 方案 / 效果）+ 完成环进一格 + 一键沉淀 |

统一约束：**300ms 内、不弹窗、不阻断、不撒花。**

## 12. 实施路径

现有 435KB / 8300 行。这是**表现层重构**。

> **铁律：现有 19 个 `DATA_KEYS` 的结构定义一个都不改。**
> 仅新增 2 键（`openItems` / `fitnessData`）+ 给 `goals/shorts/todays` 加可选字段（向后兼容，老数据不猜、标记待归类）。

| 阶段 | 内容 | 风险 |
|---|---|---|
| **P1 骨架** | MODULES 改 4 领域 + 首页 + 收尾页 + 周复盘页；四段式空槽；顶栏（**无捕捉**） | 低 |
| **P2 数据层** | 新增 `openItems` 四态状态机 + `fitnessData` + `domain` 字段；`solving` 隔日回退；ref 级联规则；老数据标记待归类 | 中（**唯一的数据层改动，做完锁死**） |
| **P3 首页** | L1 观察卡 / L2 焦点图表 / L3 今日行动（**无输入框**） | 中（图表手写 SVG） |
| **P4 计划链** | 四领域 S2 三级链 + 短期「加入今日」+ 今日可空挂 + 待归类交互 | 中 |
| **P5 领域搬家** | 现有渲染函数逐个搬到对应领域页 S1–S4；**健身五件套** | 中（遵守单向调用 DAG） |
| **P6 反馈与复盘** | 关闭卡点强反馈 + 收尾页 + 正反馈自动生成 + 变异检测 + 周复盘页 | 中 |
| **P7 收尾** | AI 降级为助手；**删饮食 / 娱乐 / 备忘 / 顶栏捕捉** | 低 |

### 必须遵守的既有铁律

- 页面 id 必须等于 `page-<key>`（否则 `go()` 找不到、点了没反应）
- 单向调用 DAG：`store → xxxCheckin() → renderXxx() → go(key)`，渲染函数之间严禁互调
- 写操作一律走「预览卡 → 确认 → 快照入栈」
- 图标全手写 SVG，禁用 emoji
- **清空数据必须连 AI 记忆一起清**；**密钥是配置不是数据**（`llm_configs` / `asr_cfg` 保留）
- **导出安全守卫**：`/key|token|secret/i` 一律剔除；`firstUseDate` 不在导出链路
- 改完先同步 `我的生活台启动包/` 副本，再跑 `test-m6.js` / `test-m9.js`
- **present_files 会污染源文件** —— 只在 push 之后调用
