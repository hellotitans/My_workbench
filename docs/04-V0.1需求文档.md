# V0.1 需求文档 · 语音与智能对话模块

> 版本：V0.1 ｜ 日期：2026-09-18 ｜ 状态：待开发
> 上游：V0.0 已归档（GitHub hellotitans/My_workbench，tag v0.0）

---

## 一、需求背景

用户希望工作台不只是"记录工具"，而是能**用自然语言交代它做事**：说话或打字，让它帮忙打卡、记录、查询，并逐步理解自己的习惯与偏好。

讨论中确立的三条前提：

1. **不做端到端语音模型**。端到端模型当前不支持 Function Calling，而"操控工作台"这一核心诉求必须靠工具调用实现。
2. **架构采用"语音外壳 + 文本大脑"**。这也是 OpenAI GPT-Live-1 与 Gemini Live 的主流设计（语音层只管听说，推理与工具调用委托后端文本模型）。
3. **V0.1 只做 a：文本 + 工具调用，自用验证**。语音输入输出留到 V0.2，但接口层现在就按可替换设计好。

## 二、范围界定

### 本次（V0.1）要做的

| 编号 | 模块 | 一句话 |
|---|---|---|
| M1 | LLM 接入层 | 通用 OpenAI 兼容适配，用户自填 Base URL / 模型名 / Key，多组可切换 |
| M2 | 对话模块 | 新板块，流式文本对话，历史存本地 |
| M3 | 工具调用 | 暴露工作台读写工具，**写操作必须预览 + 确认 + 可撤销** |
| M4 | 用户记忆 L0 | 可编辑的用户画像 + 记忆写入闸门（写入权限 / 遗忘 / 防幻觉） |
| M5 | 声场球 | 移植 3D_soundfield 粒子球，作为对话区的语音/状态可视化 |

### 本次不做的（明确划界）

- 语音识别（ASR）与语音播报（TTS）——留到 V0.2，但架构上不阻塞
- 后端服务 / 账号体系 / 多用户
- 自动记忆摘要（L2 层）——留到 V0.2，L0/L1 先跑稳
- 商品化改造（统一计费、订阅）——留到验证之后

## 三、模块需求

### M1 LLM 接入层

- 配置项：`Base URL` / `模型名` / `API Key` / `显示名`，支持保存多组并下拉切换
- 内置预设：DeepSeek、阿里云百炼、火山方舟、智谱、Moonshot、硅基流动、OpenAI（用户填 Key 即可用）
- 提供「测试连接」按钮：发一条最小请求，明确回报成功 / 失败原因（401 / 404 / CORS / 超时）
- **API Key 必须排除在 `exportJSON()` 之外**（V0.0 的导出会连配置一起带走，属已识别隐患）
- Key 在界面上默认掩码显示，可一键清除

**验收点**：填入硅基流动 / DeepSeek 的 Key 后测试连接通过；导出 JSON 文件中不含任何 key 字段。

### M2 对话模块

- 侧边栏新增「对话」板块，进入后为聊天界面（消息流 + 输入框）
- 输出**流式**返回（SSE），逐字上屏；中断按钮可停止生成
- 历史会话按天分组存本地，可清空、可继续上文（保留最近 N 轮）
- 未配置 Key 时显示明确引导，而不是报错或空白

**验收点**：发送一条消息能看到流式上屏；刷新页面后历史仍在；清空后不报错。

### M3 工具调用

- 暴露工具集（V0.1 首批）：`打卡`、`添加待办`、`完成待办`、`记一笔心得`、`查询今日状态`、`查询某板块记录`
- **写操作三步走**：模型提出 → 页面展示"将要做什么"的预览卡 → 用户确认 → 执行 → 提供「撤销」入口（保留操作前快照，至少可撤销最近 5 次）
- 读操作无需确认，直接执行
- 工具调用失败要可见：说明失败原因，不让用户以为是模型在瞎说

**验收点**：说"帮我记一下今天喝了 3 杯水"→ 出现预览卡 → 确认 → 喝水打卡数变化 → 撤销后恢复原值。

### M4 用户记忆 L0

- 提供一个**用户可编辑的画像文本区**（默认有引导模板），每次请求作为系统提示的一部分注入
- 记忆写入闸门（详见技术文档）：模型只能输出结构化提议，由代码校验 + 用户确认后入库
- 记忆列表可见、可删、可置顶、可编辑——**不做黑盒**

**验收点**：在画像里写"我不喜欢被称呼为亲"，随后对话中模型不再使用该称呼；模型提议写入一条记忆时，必须出现确认卡片。

### M5 声场球（3D_soundfield 移植）

- 移植 `AudioEngine` + `SphereRenderer` 核心，砍掉原项目自带的 HUD / 性能面板 / 启动遮罩
- 三态表现：
  - **待机**：缓慢自转，低幅度呼吸
  - **聆听**（麦克风开启）：随声波震动
  - **思考**（等待 LLM 返回 / 流式生成中）：脉冲式起伏
- 配色跟随工作台主题（亮/暗）
- **仅在对话板块激活时运行**，离开必须停止 `requestAnimationFrame` 与麦克风轨道——否则后台常驻录音（系统麦克风指示灯会亮）

**验收点**：进入对话板块球体转动；点麦克风后随声波动；切到其他板块后麦克风指示灯熄灭、rAF 停止。

## 四、非功能性需求

- **零外部依赖**：不引入任何 CDN / 框架 / 字体。声场球为手写 Canvas 2D，随主文件内联
- **遵守单向调用铁律**：声场球与对话渲染函数之间严禁互调，统一由调度入口按序调用
- **离线可用**：未配置 Key 时其余功能不受影响
- **降级明确**：CORS 失败 / 401 / 模型不支持工具调用，都要给出人话提示，不能静默失败

---

## 五、不在本次范围的风险项（需记录在案）

1. 国产模型 `tool_calls` 稳定性参差，需重试与结果校验
2. 本地双击（`file://`）打开时麦克风行为不确定，V0.1 的声场球以线上 https 版为主战场
3. 上下文长度：历史会话 + 记忆 + 工具定义会挤占窗口，需限制轮数与注入条数
